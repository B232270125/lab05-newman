# Лаб 5: Newman-аар API тест автоматжуулах

- Оюутан: А.Адъяахүү
- Код: B232270125

## Орчин

```
$ node -v
v26.13.1
$ newman -v
6.2.3
```

Тестлэх систем: `server.js` (хичээлд бүртгүүлэх API, `http://localhost:3000`). Тестлэгдэх гол функц нь `POST /registrations`.

## Тест дизайн

### Сонголтууд ба төлөөлөх утгууд

| Сонголт | Ангилал | Төлөөлөх утга |
|---|---|---|
| studentID-ийн хүчинтэй байдал | идэвхтэй | `status: "active"` |
| | идэвхгүй | `status: "inactive"` |
| | байхгүй | бүртгээгүй ID |
| Оюутны үзсэн хичээлүүд | урьдачийг хангана | `coursesTaken: ["CS201"]` |
| | хангахгүй | `coursesTaken: []` эсвэл өөр хичээл |
| courseID-ийн хүчинтэй байдал | байгаа | PUT-аар үүсгэсэн хичээл |
| | байхгүй | бүртгээгүй ID |
| Хичээлийн урьдач нөхцөл | бүгд үзсэн | `["CS201"]`, оюутан CS201 үзсэн |
| | огт үзээгүй | `["CS201"]`, `coursesTaken: []` |
| | зарим нь | `["CS201","CS202"]`, оюутан зөвхөн CS201 үзсэн |
| | урьдачгүй (хязгаар) | `prerequisites: []` |

### Боломжгүй хослол

- Оюутан байхгүй үед үзсэн хичээл гэж байхгүй тул "байхгүй оюутан + урьдач хангана/хангахгүй" хослол утгагүй.
- Хичээл байхгүй үед урьдач нөхцөл гэж байхгүй тул "байхгүй хичээл + урьдач бүгд үзсэн" хослол утгагүй.
- Иймд сонголтуудын бүх үржвэрийг биш, зөвхөн утга бүхий хослолуудыг спецификаци болгосон.

### Спецификацийн хүснэгт

| № | Төрөл | Нөхцөл | Хүлээгдэх статус | Хүлээгдэх result |
|---|---|---|---|---|
| S1 | Happy path | Идэвхтэй оюутан, CS201 үзсэн, хичээлийн урьдач CS201 | 201 | `OK` (registrationID тоо) |
| S2 | Алдаа | Оюутан байхгүй, хичээл байгаа | 200 | `ERROR_NO_STUDENT` |
| S3 | Алдаа | Оюутан идэвхгүй, хичээл байгаа | 200 | `ERROR_INACTIVE_STUDENT` |
| S4 | Алдаа | Оюутан идэвхтэй, хичээл байхгүй | 200 | `ERROR_NO_COURSE` |
| S5 | Алдаа | Урьдач [CS201, CS202], оюутан зөвхөн CS201 үзсэн | 200 | `ERROR_PREREQUISITES`, missing = ["CS202"] |
| S6 | Давхар алдаа | Оюутан байхгүй + хичээл байхгүй | 200 | `ERROR_NO_STUDENT` |
| S7 | Давхар алдаа | Оюутан идэвхгүй + урьдач дутуу | 200 | `ERROR_INACTIVE_STUDENT` |
| S8 | Хязгаар | Хичээл урьдачгүй (`prerequisites: []`) | 201 | `OK` |
| S9 | Хязгаар | Хоосон `coursesTaken: []`, урьдач [CS201] | 200 | `ERROR_PREREQUISITES`, missing = ["CS201"] |
| S10 | Хязгаар | `courseID` талбар дутуу | 400 | `ERROR_BAD_REQUEST` |
| S11 | Хязгаар | `studentID` талбар дутуу | 400 | `ERROR_BAD_REQUEST` |
| S12 | Хязгаар | Буруу JSON бие | 400 | `ERROR_BAD_JSON` |

Давхар алдааны хүлээгдэх үр дүн (S6, S7) нь `server.js`-ийн шалгалтын дараалалтай (оюутан байгаа эсэх, идэвхтэй эсэх, хичээл байгаа эсэх, урьдач) нийцсэн.

## Collection

`lab05-collection.json` нь 12 folder (S1-S12) агуулна. Folder бүр өөрийн setup PUT-тай, өөр өөр ID (`S1_stu`, `S1_crs` гэх мэт) ашигладаг тул тест бүр бие даасан. `registrationID`-ийн яг утгыг биш, зөвхөн тоо мөн эсэхийг шалгасан. Нийт 26 request, 12 test-script, **28 assertion**.

## Newman ажиллуулалтын үр дүн

| Ажиллуулалт | Файл | assertions executed | assertions failed | exit code |
|---|---|---|---|---|
| PASS | `results/newman-pass.txt` | 28 | 0 | 0 |
| FAIL | `results/newman-fail.txt` | 28 | 1 | 1 |
| DOWN | `results/newman-down.txt` | 0 | 0 (26 request errored) | 1 |
| Нийтийн API (нэмэлт) | `results/newman-public.txt` | 3 | 0 | 0 |

- **PASS**: 12 спецификаци бүгд хүлээгдсэнээр ажиллав. S6, S7 (давхар алдаа)-ын бодит үр дүн `server.js`-ийн шалгалтын дараалалтай таарав: оюутан байгаа эсэх, идэвхтэй эсэх, хичээл байгаа эсэх, урьдач.
- **FAIL**: `lab05-collection-fail.json`-д S1-ийн статусын oracle-ыг зориуд 201-ийн оронд 200 гэж хүлээлгэсэн. Сервер 201 буцааснаар 1 assertion fail болж, exit code 1 гарав. Ингэж CI quality gate шалгалтыг амжилтгүй болгодог. Үндсэн `lab05-collection.json` зөв хэвээр үлдсэн.
- **DOWN**: сервер унтарсан үед `ECONNREFUSED` гарч, 26 request бүгд errored болов. Assertion нэг ч ажиллаагүй (0 executed).

### FAIL ба DOWN-ын ялгаа

FAIL нь сервер хариу өгсөн боловч oracle хүлээсэн утгатай таарахгүй байсан oracle-ийн алдаа бол DOWN нь сервертэй холбогдож чадаагүй интерфейсийн алдаа бөгөөд тэнд assertion огт ажиллаагүй.

## Даалгавар 5: Нийтийн API

`lab05-public-api.json` нь `https://jsonplaceholder.typicode.com/users` руу GET хийж 3 oracle шалгана (статус 200, массив эсэх, эхний хэрэглэгчийн нэр `Leanne Graham`). 3 assertion бүгд PASS, exit 0.

Энэ нь GET-only тул setup хэрэггүй, нэг request-ээр шалгагдсан учир өөрийн API-аас хялбар байсан. Харин өөрийн API дээр тест бүрд setup PUT хийж, бие даасан байлгах хэрэгтэй байсан.

## Дүгнэлт

Энэ лабт би хичээлд бүртгүүлэх API-г Postman collection-оор тестлээд Newman-аар автоматаар ажиллуулж сурлаа. Тест дизайны алхмуудаас хамгийн их бодол шаардсан нь боломжгүй хослолуудыг ялгаж, спецификацийн хүснэгтээ гаргах хэсэг байсан. Сонголтуудын бүх хослолыг тест болгох шаардлагагүй, утга бүхий хослолоо л сонгоно гэдгийг ойлгосон. Боломжгүй хослолоос хоёр таарсан: байхгүй оюутан дээр үзсэн хичээл гэж байхгүй, байхгүй хичээл дээр урьдач нөхцөл гэж байхгүй. Давхар алдааны S6, S7 дээр сервер аль алдааг түрүүлж буцаахыг заавар заагаагүй тул server.js-ийн шалгалтын дарааллаар таамаглаж README-д бичсэн, дараа нь тестээ ажиллуулж ERROR_NO_STUDENT, ERROR_INACTIVE_STUDENT гарч байгааг баталгаажуулсан. Тестүүд серверт ямар нэг согог олсонгүй, 12 спецификаци бүгд хүлээсэн үр дүнтэй таарсан. Харин collection-оо анх ажиллуулахад S5, S9-ийн missing шалгалтын скриптэд синтакс алдаа гарч 2 test-script унасан, шалгалтын нэр доторх хашилтыг засаад дахин ажиллуулж 28 assertion бүгд PASS болсон. FAIL ажиллуулалтаар нэг oracle буруу байхад exit code 1 гарч байгааг харсан, CI дээр тест унавал pipeline ингэж зогсдог. DOWN ажиллуулалтад сервер унтарсан үед нэг ч assertion ажиллаагүй, энэ нь oracle-ийн алдаа биш холболтын алдаа гэдгийг ялгаж ойлгосон. Мөн tee-ийн дараа exit code-ыг $?-оор биш ${PIPESTATUS[0]}-оор авах ёстойг мэдсэн.
